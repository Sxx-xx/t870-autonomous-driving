[조종기 arming] (2026-09-14 적용)
- 목표: MANUAL 상태에서 launch를 미리 띄워두고, 조종기를 AUTO로 올리면
  그때 GPS 추종이 시작되도록 함.

- 확인된 사실:
  조종기 AUTO/MANUAL은 원래 아두이노 펌웨어 레벨 게이트였고 ROS와 무관했음.
  RC 수신기 D6 -> 보조 Arduino(pwm_receiver_bridge.ino) -> I2C -> 메인 Arduino
  AUTO  : 조향 = Pixhawk PWM(SERVO9), 속도 = USB 시리얼 명령
  MANUAL: 조종기 조향/스로틀 직접 사용, ROS 명령 완전 무시
  /mavros/rc/in 을 구독하는 코드는 워크스페이스에 없었음.
  /t870/control_mode 를 발행하는 곳은 웹 UI 하나뿐이었음.

- 펌웨어는 손대지 않아도 됐음:
  sketch_aug.ino 의 printStatus()가 이미 "RC:AUTO|MANUAL|LOST"를 출력하고
  arduino_drive_node 가 이미 그 줄(Act: 포함)을 읽고 있었음.
  Arduino 재업로드 불필요, 배선 변경 불필요.

- 같이 고친 버그:
  gps_path_follower_node 의 bounded_nearest_index 는 첫 fix에서 인덱스를 잡은
  뒤 max(previous_index, ...) 때문에 뒤로 갈 수 없었음. MANUAL로 런치하고
  차를 수동으로 경로 시작점까지 옮기면 인덱스가 런치 지점에 고정되어
  STOP_ROUTE_ERROR 만 나고 회복 불가였음.

- 변경한 파일:
  1) t870_control/arduino_drive_node.py
     텔레메트리에서 RC 상태 파싱 후 발행
     /t870/remote_auto (Bool), /t870/remote_rc_mode (String)
  2) t870_control/remote_mode_control_node.py
     /t870/remote_auto 구독.
     MANUAL->AUTO 엣지에서 rc_arm_mode(기본 GPS) 선택,
     AUTO->MANUAL 엣지에서 즉시 STOP.
     selected_command 상시 가드: 조종기가 MANUAL이거나 RC 텔레메트리가
     rc_timeout_sec(1.5s) 이상 끊기면 웹 UI 조작과 무관하게 STOP 강제.
     신규 파라미터: rc_arm_enabled, rc_arm_mode, rc_timeout_sec
  3) t870_control/gps_path_follower_node.py
     /t870/control_mode 구독. GPS 모드로 진입할 때마다
     nearest_initialized=False 로 리셋해 경로 전체에서 최근접 waypoint 재획득.
  4) launch/t870_indoor_lidar.launch.py, launch/t870_lane_autonomy.launch.py
     rc_arm_enabled / rc_arm_mode 인자 추가 및 전달

- 동작 순서:
  MANUAL로 launch -> 모드 STOP 유지, 차 정지
  -> 조종기 AUTO 전환 -> 모드 GPS 자동 전환 + 최근접 waypoint 재획득
  -> Arduino 전환 정지 1초(MODE_CHANGE_STOP_MS) 후 주행 시작
  -> 조종기 MANUAL로 내리면 즉시 STOP, 조종기 직접 조작으로 복귀

- 확인 토픽:
  ros2 topic echo /t870/remote_rc_mode   (AUTO / MANUAL / LOST)
  ros2 topic echo /t870/control_mode     (STOP -> GPS 전환 확인)

[heading 폴백 해결] (2026-09-14 23시, 적용 완료)

증상: 저속에서 방향이 조금만 틀어져도 조향이 확 꺾이며 경로를 이탈하고,
      그 뒤로는 영영 경로를 못 따라감. 속도가 붙으면 잘 따라감.

원인 1 - corrected_imu 가지가 코드상 도달 불가였다.
  current_heading() 의 조건이 이랬다:
    if (self.heading_offset is not None and self.imu_yaw is not None ...):
        offset = (self.heading_offset
                  if self.heading_offset is not None else self.imu_yaw_offset)
  앞의 heading_offset is not None 때문에 뒤의 imu_yaw_offset 폴백은 죽은 코드였다.
  heading_offset 은 align_initial_heading_if_ready() 에서만 설정되는데 그 함수는
  not self.relative_route 이면 즉시 return 한다. 1.csv 는 절대 WGS84 경로라
  heading_offset 이 영원히 None -> IMU heading 이 전혀 쓰이지 않았다.
  결국 GPS course 가 없는 저속에서는 route_tangent(경로 접선을 heading 이라고
  가정하는 값) 밖에 없었고, 실측 heading 오차가 20~40도였다.

원인 2 - route_tangent 에서 gps_course 로 바뀌는 순간의 계단 입력.
  오늘 로그 18회 전환에서 heading 점프 평균 39.6도(최대 168도),
  전환 직후 1초 조향 변화폭 평균 0.117 rad(한계 0.20의 59%).

수정한 것:
  1) current_heading() 조건에서 heading_offset is not None 제거.
     MAVROS /mavros/imu/data 는 FCU 자세를 ENU 로 발행하므로 yaw 가 이미
     atan2(north, east) 와 같은 규약의 절대방위다. imu_yaw_offset_rad(0.0)
     가 트림 역할만 한다. 정지 상태에서도 실제 heading 을 얻는다.
  2) velocity_callback 에 align_imu_to_course() 추가. GPS course 가 유효할
     때마다 IMU 오프셋을 저역통과(imu_align_gain 0.02)로 추종한다.
     IMU 드리프트를 따라가면서 course 가 끊겨도 heading 을 유지한다.
  3) route_tangent_max_steer_rad 신설. heading 이 경로 접선 추측일 때만
     조향을 제한한다. 0.05 로 넣었다가 선회 반지름이 14.5 m 가 되어 경로
     복귀가 불가능했고(차가 얼라이 틀어진 것처럼 계속 한쪽으로 감),
     0.15(반지름 4.8 m)로 올려 복귀 가능하게 했다.

결과 (gps_tracking_20260914_232150.csv, 정상 추종 구간 65초):
  route_tangent    60~79%  ->  0.1% (2행)
  corrected_imu    0(도달불가) -> 878행
  heading 오차     20~40도 ->  3.8도
  조향 포화        100%    ->  0%
  경로오차         평균 0.73 m, 최대 1.99 m, 1 m 이내 73%
  속도             최대 2.29 m/s (8.3 km/h)

[LAD 밴드 정리] (2026-09-14 23시)

LAD = Lookahead Distance. 경로 위에서 겨냥할 점까지의 거리.
짧으면 같은 오차에 세게 꺾고(정확하지만 흔들림), 길면 완만하다(부드럽지만
코너를 자름). 축거 0.725 m 기준 경로에서 1 m 벗어났을 때:
  LAD 2.0 m -> 조향 0.348 rad (선회 반지름  2.0 m)
  LAD 5.0 m -> 조향 0.058 rad (선회 반지름 12.5 m)
  LAD 7.0 m -> 조향 0.030 rad (선회 반지름 24.5 m)

경과:
  원래     2.0 / 2.7 / 3.5 / 6.0 / 7.0
    저속 LAD 2.0 m 에서 비례구간이 16도뿐이라 GPS heading 노이즈(±30도)에
    좌우 풀락으로 튕겼다. 3.5 / 4.0 으로 올려 해결.
  사용자 조정  7.0 / 5.0 / 3.5 / 6.0 / 7.0
    출발 튐을 줄이려고 저속만 올렸는데 6 km/h 밴드가 3.5 로 남아 V자가 됐다.
    가속 중 경계에서 조향 게인이 1.43배 급증 후 0.58배 급감.
    실제 피해: 2026-09-14 23:05 주행에서 E-stop 으로 감속하다 속도가 2 km/h
    아래로 떨어지는 순간 LAD 가 5.0 -> 7.0 으로 올라가 게인이 0.71배가 됐고,
    경로 복귀해야 할 시점에 오히려 힘이 빠져 오차가 1.89 -> 6.97 m 로 벌어졌다.
  현재     5.0 / 5.0 / 5.5 / 6.0 / 7.0  (단조 증가)
    경계 게인 변화 최대 0.92배. 계단이 사실상 없다.
    비례구간 44.3 / 44.3 / 50.3 / 57.0 / 78.1 도.

[분석 시 반드시 먼저 할 것]

tracking CSV 는 조종기가 MANUAL 이어도 follower 가 계속 기록한다.
state 가 TRACKING 이라고 해서 차가 ROS 제어로 움직인 것이 아니다.
오늘 이 함정에 세 번 빠져 MANUAL 주행을 자율주행 성능으로 오판했다.

판별: 조향 명령 대비 실제 선회량을 부호 포함해 비교한다.
  dheading/dt = -v * tan(delta) / L      (positive_right=True 이므로 음부호)
  2초 창으로 나눠 (실제 방위변화 / 예상 방위변화) 의 중앙값을 본다.
  0.4 이상이면 AUTO, 0 근처면 MANUAL 이거나 조향이 바퀴에 안 간 것.
  |조향| 누적과 순 회전량을 비교하면 좌우 보정이 상쇄되어 AUTO 도 MANUAL 로
  잘못 나온다. 반드시 부호를 맞출 것.

조향이 안 간 또 다른 원인: MAVROS 가 꺼져 있으면 /mavros/rc/override 가 갈
곳이 없어 조향이 죽고, /mavros/imu/data 도 끊겨 heading 까지 없어진다.
2026-09-14 22:52 주행 두 건이 이 경우였다.

AUTO 구간을 확실히 알려면 주행 중 다음을 띄워 파일로 남긴다:
  ros2 topic echo /t870/remote_rc_mode | grep --line-buffered "^data:" | \
    while read -r l; do [ "$l" != "$p" ] && echo "$(date +%H:%M:%S) $l" \
    | tee -a /tmp/rc_mode_log.txt; p="$l"; done
  (같은 방식으로 /t870/emergency_stop 도 /tmp/estop_log.txt 에)

[주의]
- 터미널 2의 topic echo는 모니터링만 하며 GPS 추종을 시작/초기화하지 않음.
- USB 장치 경로(/dev/serial/by-id/...)가 실제 연결 상태와 일치해야 함.
- 주행 중 GPS가 STOP_ROUTE_ERROR로 바뀌는지 tracking CSV와 터미널 로그를 확인.
- RC 상태는 오직 Arduino USB 시리얼로만 ROS에 들어옴. arduino_drive_node가
  포트 연결에 실패하면 /t870/remote_auto가 오지 않아 타임아웃으로 모드가
  STOP에 머무름. AUTO로 올려도 안 움직이면 여기부터 확인할 것.
- AUTO 전환이 곧 출발임. 실차 첫 시험은 바퀴를 띄우거나 넓은 공터에서,
  조종기 MANUAL로 즉시 회수 가능한 상태로 진행할 것.
