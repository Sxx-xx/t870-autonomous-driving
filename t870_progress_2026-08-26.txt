2. 실차에서 확정한 배선 기준
----------------------------

2.1 Pixhawk -> Arduino

  B-Cube FMU PWM OUT 1의 S(신호) -> Arduino D8
  B-Cube FMU PWM OUT 1의 GND     -> Arduino GND
  B-Cube FMU PWM OUT 1의 +       -> 연결하지 않음

  현재 CH1 신호선과 GND 연결 완료.


2.2 Arduino 핀 배치

  D2  : 구동 엔코더 A상
  D3  : 구동 엔코더 B상
  D7  : 조향 MD20A DIR
  D8  : Pixhawk CH1 PWM 입력
  D9  : 조향 MD20A PWM
  D10 : 구동 MDD20A PWM1
  D11 : 구동 MDD20A DIR1
  A0  : 조향 포텐셔미터 와이퍼


2.3 구동 MDD20A 및 엔코더 색상

  MDD20A M1A : 노란색 구동모터선
  MDD20A M1B : 파란색 구동모터선

  엔코더 초록색 A상 -> Arduino D2
  엔코더 파란색 B상 -> Arduino D3

  위 배선에서 차량 전진 시 엔코더 카운트가 양수로 증가하는 것을 확인함.
  따라서 Arduino 코드의 ENCODER_SIGN = 1이 맞음.

  2026-08-27 실제 명령 시험으로 확정한 방향:
    DIR HIGH = 전진
    DIR LOW  = 후진

  전진할 때 엔코더 카운트는 양수,
  후진할 때 엔코더 카운트는 음수로 들어오는 것을 확인함.


2.4 조향 MD20A 및 포텐셔미터

  MD20A MA : 초록색 조향모터선
  MD20A MB : 흰색 조향모터선

  실차 버튼 확인:
    MA 버튼 = 우회전
    MB 버튼 = 좌회전

  포텐셔미터 확인:
    좌회전할수록 측정값 감소
    우회전할수록 측정값 증가

  측정 기준값:
    좌측 끝 = 약 40
    중앙    = 약 485
    우측 끝 = 약 984

  소프트 제한:
    좌측 = 55
    우측 = 969

  Arduino 코드 방향 기준:
    DIR LOW  = MA = 우회전 = POT 값 증가
    DIR HIGH = MB = 좌회전 = POT 값 감소

9. 현재 결론
-------------

Pixhawk 조향 PWM 출력부터 Arduino D8 입력, 포텐셔미터 위치 피드백,
MD20A 실제 조향모터 구동까지 전체 조향 경로가 정상 동작하는 것을 확인했다.
SERVO9는 Ground Steering으로 설정했고 1100/1500/1900us 범위를 사용한다.

MDD20A 구동은 전후진 방향과 엔코더 부호를 확정했고, 최소 PWM을 5로
보정하여 기존 저속 펄스 현상을 제거했다. 바퀴 10회전 측정 결과를 반영해
COUNTS_PER_REV를 149.8로 수정했다. 바퀴를 띄운 시험에서 전진과 후진 모두
±0.3 km/h 목표에 대해 약 ±0.27~±0.34 km/h로 안정적으로 수렴했다.

ROS /cmd_vel의 linear.x를 Arduino USB 시리얼로 전달하는 노드가 구현되었고,
지면에서 +0.06/-0.06 m/s 명령이 각각 +0.216/-0.216 km/h로 전달되어
전진과 후진하는 것을 확인했다. Pixhawk CH3 구동 출력은 제거되어 현재
구동은 Arduino만 담당한다. 명령 중단 시 안전정지도 확인했다.

ROS angular.z 조향 통합 경로도 완료했다. 초기에는 MAVROS 송신 system_id가
1이고 Pixhawk MAV_GCS_SYSID가 255라 RC Override가 거부되었다. MAVROS를
system_id=255로 실행한 뒤 CH1 1786 명령이 SERVO9 약 1776으로 출력되는 것을
확인했다. 실제 조향 방향이 ROS 규칙과 반대여서 reverse_steering_output을
추가했고, 현재 최종 규칙은 +angular.z=우회전, -angular.z=좌회전이다.

지상에서 linear.x=0.10 m/s 상태의 전진+좌회전과 전진+우회전을 모두
성공했고 명령 종료 시 구동 정지와 조향 중앙 복귀도 확인했다. 따라서
ROS 기본 구동(전진, 후진, 좌회전, 우회전, 복합 조향)은 정상 완료 상태다.

현재 LiDAR/RRT/추종/원격모드/Pixhawk/Arduino 제어는 실내 통합 launch로
실행하며, MAVROS는 ABI 충돌 방지를 위해 시스템 MAVROS를 별도 터미널에서
system_id=255로 실행한다. 남은 핵심 작업은 새 MANUAL E-stop 후진/조향
탈출 동작과 실제 통신 단절 안전시험을 수행하는 것이다. 현재 중앙 목표
PWM 1500/POT 485가 실제 직진 바퀴각과 맞는지 확인하는 작업은 충분한
속도와 직진거리가 필요한 실외 시험이므로 후순위로 미룬다. 실외 시험에서
좌우 쏠림이 확인되면 기계적 중앙값을 다시 측정해 Arduino 중앙값을
보정한다. GPS/IST8310 도착 후
임시 COMPASS_ENABLE=0 설정을 반드시 1로 복원하고 외장 나침반 보정과
RTK/EKF 확인을 해야 한다. 이후 LiDAR E-stop 및 자율주행 파라미터 튜닝을
진행한다.

- 처리 순서: 원본 영상 -> 사다리꼴 ROI -> Bird's-Eye View -> 차선 후보 검출 ->
  좌우 안쪽 차선 선택 -> 중앙 경로 -> /cmd_vel/lane.
- LiDAR RRT와 GPS 경로 알고리즘에는 Bird's-Eye View를 사용하지 않는다.
- 최종 카메라 각도, ROI, Canny 및 원근변환 기준은 현장에서 조정한다.

5. GPS 이동 경로 기록시험 결과
-------------------------------
- 차량 전체 구동 없이 t870_gps_record.launch.py만 사용해 GPS 기록시험을 수행했다.
- 시험 설정: path_name=gps_move_test, minimum_distance_m=0.5,
  start_recording=true.
- [완료/검증] GPS 점 50개가 정상 저장됐다.
- 인접점 누적거리 약 29.79m, 시작점과 마지막 점 사이 직선거리 약 22.21m.
- 위경도 범위:
  - longitude 129.086820 ~ 129.087083
  - latitude 35.075228 ~ 35.075303
- UTM zone: 52N.
- 저장 파일:
  - gps_recordings/gps_move_test.csv
  - gps_recordings/gps_move_test.txt
- 같은 path_name 파일이 존재하면 안전상 덮어쓰지 않으므로 다음 시험은 새로운
  이름을 사용한다.

6. GPS 경로 시각화
------------------
- 실시간 ROS 경로 토픽: /gps/recorded_path
- 점 개수 토픽: /gps/recorded_point_count
- RViz 설정: Fixed Frame=utm, Path 표시 토픽=/gps/recorded_path.
- 기록 노드 종료 후에는 기존 Path를 새 RViz 구독자에게 재전송하지 않으므로,
  RViz를 먼저 실행하고 GPS 기록을 시작해야 실시간 표시가 확실하다.
- 지도 확인용 KML 변환 완료:
  gps_recordings/gps_move_test.kml
- KML에는 WGS84 위경도 GPS 점 50개가 들어 있으며 Google Earth 또는 QGIS에서
  열 수 있다. Google My Maps 파일 가져오기는 Google 계정 로그인이 필요하다.
