2. [구현됨] 후진 주행
===============================================================================
경로 파일의 target_speed 부호로 전/후진을 가린다.

  target_speed  +2.7778   전진 10 km/h
  target_speed  -1.0000   후진 3.6 km/h

켜는 법: 주행 명령에 gps_allow_reverse:=true
  (기본은 꺼짐. 안 주면 음수 target_speed 는 무시되고 전진한다.)

구현 요점 (gps_path_follower_node.py)

  (a) 후진 판정은 '지금 서 있는' 웨이포인트로 한다.
      segment_speed = self.points[nearest][2]
      목표점(LAD 앞)으로 판정하면 8 m 미리 후진으로 바뀐다.

  (b) 조향 부호를 뒤집는다. 이 한 줄이 후진 pure pursuit 의 전부다.
          if want_reverse:
              steering = -steering
      heading(gps_course 든 route_tangent 이든)은 둘 다 '진행 방향' 이라
      후진 중에도 그대로 쓸 수 있다. 바뀌는 것은 조향 부호뿐이다.
      앞바퀴가 뒤따라가는 꼴이 되기 때문이다.
      검산: 경로가 진행방향 기준 왼쪽으로 꺾일 때(alpha +30도)
            전진 +0.237 rad(좌회전) / 후진 -0.237 rad(우조향, 뒤가 왼쪽).

  (c) 기어 전환은 반드시 정지를 거친다.
          if measured > reverse_switch_speed_mps(0.15):
              magnitude = 0.0          state = STOP_FOR_SHIFT
          else:
              방향 전환
      펌웨어도 REVERSE_GUARD_KMH(0.3) 로 같은 보호를 한다. 굴러가는 중에
      DIR 핀을 뒤집으면 역전 제동이 걸려 드라이버와 모터에 큰 전류가 흐른다.
      follower 가 먼저 세워야 전환 지점이 예측 가능해진다.

  (d) 전환 직후 옛 course 를 버린다.
          self.gps_course_time = 0.0
      진행 방향이 180도 바뀌므로 직전 course 는 정확히 반대다. 그대로 쓰면
      반대로 꺾으며 발산한다. 새 course 가 올 때까지 경로 접선을 쓴다.

  (e) 후진 구간에서는 route_tangent 조향 클램프를 푼다.
      route_tangent_max_steer_rad 는 0.0 이라 평소에는 조향이 0 으로 묶인다.
      전환 직후에는 새 course 가 없어 반드시 route_tangent 으로 떨어지는데,
      거기서 조향이 0 이면 주차 조작 자체가 성립하지 않는다. 경로 접선은
      진행 방향과 같으므로 후진 중에도 올바른 기준이다.

트래킹 CSV 의 state 컬럼에 REVERSE / STOP_FOR_SHIFT 로 찍힌다.

구간 표시 도구
  python3 path_mark_reverse.py <csv> <시작idx> <끝idx> --speed 1.0
  python3 path_mark_reverse.py <csv> <시작idx> <끝idx> --forward   (되돌리기)
  --dry-run 으로 미리보기. 원본은 .bak 으로 남는다.

검증 완료 (2026-09-16 ~ 17)
  T 자 주차 전 과정이 실차에서 돈다. 전진 접근 -> 후진 진입 -> 정지 ->
  전진 탈출까지 이어진다. 후진 조향 부호는 맞았다.
  정차 정확도 (park_a 이전 경로 t_p2 기준, wp 21 목표)
    좌우   -0.044 m
    앞뒤   +0.444 m  -> 판정 뒤 제동 거리 0.38 m 를 보정해 reverse_overshoot_m
                       를 -0.38 로 두었다. 지금은 앞뒤도 10 cm 안쪽이어야 한다.
    정차 중 흔들림 0.030 m

경로 만들 때
  전진 ... → 칸을 지나쳐 정지 위치 → [후진 구간] 칸 안쪽 → 정지 → 전진 탈출
  전환 지점에는 점을 3~4개 촘촘히 둔다. 거기서 차가 서므로 여유가 필요하다.

3. [이미 있음] 주행 중 경로 교체
===============================================================================
한 CSV 안에 갈림길을 넣을 필요가 없다. follower 에 경로를 통째로 갈아끼우는
토픽이 이미 있다.

  /t870/set_gps_path  (std_msgs/String, 파일 경로 문자열)

  def set_path_callback(self, msg):
      points, relative = load_route(msg.data)   # 실패하면 기존 경로 유지
      self.points = points
      self.nearest_index = 0
      self.nearest_initialized = False          # 전 구간에서 최근접 재탐색

nearest_initialized 를 풀기 때문에 갈아끼운 직후 지금 차가 서 있는 자리에서
새 경로의 최근접점을 다시 잡는다. 그래서 달리는 중에 바꿔도 이어서 간다.
잘못된 파일을 주면 거부하고 기존 경로를 유지한다.

수동 시험
  ros2 topic pub --once /t870/set_gps_path std_msgs/msg/String \
    "{data: '/home/sxx/Desktop/colcon_ws./colcon_ws/colcon_ws/gps_recordings/school_B.csv'}"

경로 파일 구성 (중요)
  두 경로를 각각 '완결된 전체 경로' 로 만든다. 갈림점 전까지는 좌표가
  완전히 같아야 한다. QGIS 에서 접근 구간은 같은 점을 복사해 쓴다.
  좌표가 어긋나면 갈아끼우는 순간 차가 튄다.

    school_A.csv   ... 접근(공통) ... → 왼쪽 칸 후진 진입 → 탈출 → 끝
    school_B.csv   ... 접근(공통) ... → 오른쪽 칸 후진 진입 → 탈출 → 끝

  기본 경로로 A 를 걸고 출발한다. 콘이 왼쪽이면 B 로 갈아끼운다.

4. [구현됨] 콘 판정 노드
===============================================================================
라이다를 보는 기존 노드와 별도로 parking_slot_selector_node.py 를 만들었다.
최종 구현과 현장 실측값은 아래 11장을 본다.

  1. 차가 판정 지점(웨이포인트 N)에 들어오면 깨어난다
     -> /gps/current_waypoint (UInt32) 를 구독하면 된다
  2. /scan 에서 좌/우 두 칸 방향의 각도·거리 창을 본다
  3. 점이 뭉쳐 있는 쪽 = 콘 = 막힌 칸
  4. 반대쪽 경로 파일을 /t870/set_gps_path 로 한 번 발행하고 잠근다
     (한 번만. 왔다 갔다 하면 안 된다)

만들기 전에 현장에서 재야 할 값 세 개
  (1) 판정 시점 웨이포인트 번호
      두 칸이 라이다에 다 보이는 지점. 너무 멀면 콘이 안 잡히고 너무
      가까우면 경로를 갈아탈 여유가 없다.
  (2) 두 칸의 각도 창과 거리 창
      차가 판정 지점에 섰을 때 기준. 예 왼쪽 +60~+90도 2~5 m,
      오른쪽 -60~-90도 2~5 m.
      라이다 각도 규약은 lidar_forward_angle_deg: 180.0 으로 잡혀 있다.
  (3) 콘 판정 문턱
      그 창 안에 최소 몇 점이 몇 m 이내에 들어오면 막힌 것으로 볼지.

  추측하지 말고 실측한다. 차를 판정 지점에 세우고 콘을 한쪽에 둔 채
  /scan 을 찍으면 바로 나온다.

7. 후진/주차 로직 - 2026-09-16~17 에 겪은 것과 고친 것
===============================================================================
여러 번 헛돌았다. 같은 함정을 다시 밟지 않도록 원인과 근거를 남긴다.

[제동] 이 차는 브레이크가 없다
  펌웨어에서 duty 0 은 '관성주행' 이다. 역전 제동을 피하려고 일부러 그렇게
  해 두었다. 그래서 속도 0 을 명령해도 몇 m 를 더 간다.

  [2026-09-19 정정] 아래 '해결' 은 당시 설계다. 현재 코드와 다르다.
  follower 는 방향 전환 시 반대 부호 명령이 아니라 0 을 내보내고
  /t870/shift_estop 을 건다. 그러면 arduino 가 펌웨어 'E' 를 보내
  DRIVE_PWM 을 즉시 끊는다. 펌웨어의 AUTO_BRAKE 는 '0 이 아닌 반대 부호
  목표' 에서만 걸리므로(autoCommandNeutral 조건) 전환 중에는 발동하지
  않는다. 즉 지금 주차 전환에서 차를 세우는 것은 역토크가 아니라 관성이다.
  0.56 m/s 에서는 그것으로 충분하다는 것이 실차 결과다.
  AUTO_BRAKE 코드 자체는 그대로 남아 있고, 전환이 끝난 뒤 반대 부호 명령이
  나가는 시점에 차가 아직 굴러가고 있으면 그때 걸린다.
  해결: MANUAL 에만 있던 능동 제동을 AUTO 에도 넣었다(sketch_aug.ino).
        serialCommandSpeedKmh * actualSpeedKmh < 0 이면 제한된 역토크를
        ON 250 ms / OFF 150 ms 로 끊어 건다. 곱셈 판정이라 전->후, 후->전
        양방향 모두 걸린다. actualSpeedKmh 가 엔코더 부호를 따르는 값이라
        성립한다(명령 기준이었으면 한쪽을 못 잡았다).
        제동이 끝나고 실제로 섰으면 램프를 건너뛰고 목표 속도에서 바로
        출발한다. 안 그러면 방향 전환 뒤 소프트스타트 때문에 굼뜨다.

[전환] follower 가 전환을 미루면 안 된다
  '아직 반대로 가는 중인지' 를 판정해 미루려 했더니, 그 판정이 틀리면
  제동이 아예 안 나가거나 조향이 0 에 묶인 채 계속 굴러갔다.
  해결: 방향이 바뀌면 조건 없이 즉시 반대 부호 명령을 낸다. 펌웨어가
        세운다. 대신 전환 직후 shift_settle_sec(1.2초) 동안만 조향을
        중립으로, 웨이포인트 색인을 제자리에 묶는다. 시간 기준이라
        어떤 경우에도 교착되지 않는다.

[색인] 주차 경로는 자기 위로 되돌아온다
  전진 접근 구간과 탈출 구간이 9 cm 까지 붙는 자리가 있다. 최근접 탐색
  창이 넓으면(기본 앞 30, 한 틱 10) 후진 도중에 탈출 구간 점이 더 가깝게
  잡혀 색인이 9 -> 19 로 건너뛴다. 경로 위에 정확히 있으면 안 드러나고,
  0.4 m 만 벗어나도 바로 난다.
  해결: 주차에서는 앞 5 / 뒤 2 / 한 틱 2 로 좁힌다. 추가로 driving_reverse
        인 동안 active_run(그 방향 구간의 색인 범위) 밖으로 못 나가게 막고,
        LAD 목표점도 같은 범위로 자른다.

[첨점] 방향 전환 지점은 곡률이 아니라 첨점이다
  걸어서 딴 경로는 사람이 이어 걸어서 첨점(175~177도)이 그대로 남는다.
  이웃 구간 방위 변화가 문턱을 넘으면 그 자리를 첨점으로 보고 방향을
  뒤집는다(directions_from_cusps). 경로에 음수 target_speed 를 손으로
  넣지 않아도 된다.
  문턱은 45도. 근거: 점 간격 1.1 m 에 최소 선회 반지름 2.65 m 면 전진으로
  만들 수 있는 최대 꺾임이 23.8도다(실측 최대 23.0도). 첨점은 129~177도.
  그 사이가 통째로 비어 있어 45도면 오탐도 누락도 없다. 점 간격을 크게
  바꾸면 이 값을 다시 봐야 한다.
  첨점 '위' 의 점은 아직 이전 방향이다. 새 방향은 다음 점부터 쓴다.
  (첨점 13 -> 후진은 14 부터. 사람이 지도에서 읽는 번호와 맞춘다.)

[정지] 후진을 어디서 끝낼지는 평면으로 자른다
  최근접 색인이나 LAD 로 판정하면 경로 모양에 휘둘린다. 정지 웨이포인트를
  지나는 평면을 하나 세우고 그걸 넘었는지만 본다.
  평면의 법선은 반드시 '후진 마지막 구간' 방향이어야 한다. 그 다음 점
  방향을 쓰면(탈출 구간 방향) 후진을 시작하는 자리가 이미 평면 너머로
  잡혀서, 전/후진이 0.05초 간격으로 왔다 갔다 하며 아무것도 안 된다.
  reverse_stop_waypoint 가 -1 이면 후진 구간 끝점을 자동으로 쓴다.
  경로마다 그 번호가 다르므로(park_a 20, park_b 22) -1 로 두는 것이 맞다.
  reverse_overshoot_m 은 판정을 앞당기는 값이다. 제동 거리만큼 음수로
  준다. 실측 -0.38 m.

[재개] 재개 색인은 주차 판정 시점에 확정해 둔다
  나중에 active_run 을 보면 일반 전환 블록이 이미 전진 구간으로 덮어쓴
  뒤라 경로 끝 색인을 집어 버린다(wp 23 대신 32 로 튀었다).
  park_resume = 정지 웨이포인트 + 1 을 판정하는 순간 저장한다.

[진단] state 컬럼에 판정 변수를 같이 남긴다
  'REVERSE|w1 d1 L15' 처럼 want_reverse / driving_reverse / look 이 붙는다.
  계산과 실제 거동이 어긋날 때 이 세 개면 한 번에 갈린다. 실제로 이걸로
  'want_reverse 가 한 번도 True 가 안 됐다' 를 바로 찾았다.

9. A/B 주차 미션 - 현재 위치
===============================================================================
주차장 한 곳이 두 칸으로 나뉘고 그중 하나가 콘으로 막혀 있다. 라이다로
콘을 찾아 빈 칸으로 주차한다.

[된 것] 경로 두 개
  gps_recordings/pk_a.csv     원본 34점 (A 칸)
  gps_recordings/pk_b.csv     원본 33점 (B 칸)
  gps_recordings/park_a.csv   주행용 34점 36.0 m  첨점 [13, 20]  후진 14~20
  gps_recordings/park_b.csv   주행용 34점 36.7 m  첨점 [13, 22]  후진 14~22

  park_b 는 park_a 의 앞 15점(idx 0~14)에 pk_b 의 나머지를 이은 것이다.
  공통 구간 좌표 차이 0.000000 m. 이음새 1.35 m (평균 점 간격과 비슷).

  합칠 때 번호로 자르면 안 된다. A 34점 / B 33점이라 같은 번호라도 경로상
  위치가 한 점씩 어긋나 이음새가 2.4 m 로 벌어지고 가짜 첨점이 생긴다.
  A[14] 와 가장 가까운 B 점을 찾아(B[13]) 그 다음부터 잇는다.

[방식] 파일 두 개 + 주행 중 교체
  follower 는 CSV 한 줄씩 순서대로 따라가므로 한 파일에 갈림길을 못 담는다.
  대신 경로를 통째로 갈아끼우는 토픽이 이미 있다.

    ros2 topic pub --once /t870/set_gps_path std_msgs/msg/String \
      "{data: '<워크스페이스>/gps_recordings/park_b.csv'}"

  set_path_callback 이 nearest_initialized 를 풀기 때문에, 갈아끼운 직후
  지금 차가 서 있는 자리에서 새 경로의 최근접점을 다시 잡는다. 그래서
  달리는 중에 바꿔도 이어서 간다. 잘못된 파일은 거부하고 기존 경로를 쓴다.
  교체는 반드시 idx 14 이전에 끝나야 한다. 그 뒤로는 좌표가 갈린다.

[완료] 콘 판정 노드
  현장 측정 뒤 구현했다. 최종 방식과 값은 아래 11장을 본다.
  재는 도구: scan_check.py (아래 10장)

  노드가 할 일
    1. /gps/current_waypoint 를 구독해 판정 지점(idx 11 쯤)에 닿으면 깨어난다
    2. 정한 각도·거리 창에서 점 개수를 센다
    3. 콘이 있는 쪽 = 막힌 칸 -> 반대쪽 경로를 /t870/set_gps_path 로 한 번 발행
    4. 잠근다. 왔다 갔다 하면 안 된다

미션 조건상 두 주차구역 중 정확히 하나만 콘으로 막힌다. 초기에 현장 위치를

  주차구역 B 신호 있음 -> B 막힘 -> park_a.csv 선택
  주차구역 B 신호 없음 -> A 막힘 -> park_b.csv 선택

parking_slot_selector_node.py
  /gps/current_waypoint 가 5 이상이면 판정을 시작한다.
  차량 기준 -55~-30도, 2.8~4.5 m 창의 점을 센다.
  한 스캔에 8점 이상이면 B 감지. 5스캔 중 3회 이상이면 B 막힘이다.
  결과 경로를 /t870/set_gps_path 로 한 번 발행하고 영구 잠근다.
  판정 결과(A/B)는 result_topic 으로도 발행한다.
